2. Design flow

The order in which the system was designed and built. It is not a straight line: whenever a check fails, the design goes back to an earlier step. The orange loop is the one that actually happened in this project.

StepKey questionDecision made in this project
1. Problem definitionWhat exactly do we predict, and how do we know it works?Later cognitive impairment; success = beating age alone among people of the same age
2. Data collectionIs there labelled data, and enough of it?Sleep-EDF for staging; Challenge 2026, 6,522 people, for impairment
3. PreprocessingHow do we remove noise and make recordings comparable?0.3–35 Hz filter, 30-s epochs, z-score per recording
4. Feature engineeringWhich measurements carry the signal?49 measures chosen from sleep and dementia research
5. Model selectionWhich model fits the data type and size?Deep network for raw signals; classical models for the feature table
6. TrainingHow does the model learn without ignoring rare classes?Class-weighted loss; AdamW; regularisation
7. ValidationIs the score stable and on unseen people?Split by person; repeated 5-fold cross-validation
8. GateIs it better than the simple baseline, and honest?Found and removed the BMI leak; moved to the large dataset
9. TestingDoes it work somewhere new?Leave-one-hospital-out: beats age at all 3 hospitals
10. ExplainabilityWhy does it predict what it predicts?SHAP; top signals match medical research

3. Architecture: sleep-stage network (Part 1)

A two-stage deep neural network. The epoch encoder (a 1D convolutional neural network) reads each 30-second epoch and turns it into 2,048 numbers that describe its wave patterns. The sequence model (a bidirectional GRU) then reads 20 of these in a row, so each epoch is scored with 10 minutes of context, as a human expert would.

Why each layer is there

LayerPurpose
Wide first convolution (k = 50, 0.5 s)Long enough to "see" a whole slow wave or spindle; stride 6 reduces the length early to save computation
Batch normalisationKeeps each layer's values in a stable range, so training is faster and more reliable
ReLUNon-linear activation; lets the network learn shapes, not just weighted sums
Max-poolingKeeps the strongest response in each window; shrinks the data and makes detection tolerant to small shifts in time
Three narrow convolutions (k = 8)Combine the simple shapes found by the first layer into more complex patterns
Dropout 0.5Randomly switches off half the values during training, so the network cannot rely on any single one: prevents overfitting
Bidirectional GRUA recurrent layer with memory. Forward direction remembers what came before, backward what comes after; sleep stages follow typical transitions
Linear + softmaxTurns the 256 numbers into 5 probabilities, one per stage, summing to 1

Training settings (hyperparameters)

SettingValueMeaning
Loss functionWeighted cross-entropyPenalises wrong stages; rare stages (N1, N3) weighted more
OptimiserAdamWAdaptive gradient descent with weight decay
Learning rate0.001, cosine scheduleStep size, slowly reduced during training
Weight decay0.001Regularisation: keeps weights small
Batch size16 sequences × 20 epochs320 epochs per training step
Gradient clipping5.0Stops very large updates that make GRUs unstable
Early stoppingPatience 6Stop when validation score has not improved for 6 rounds; keep the best model
Data split157 / 20 / 20 recordingsTrain / validation / test, split by person
HardwareGTX 1650 laptop GPUAbout 9 minutes; stopped at round 17, best at round 11

4. Architecture: cognitive impairment risk (Part 2)

Part 2 is a classical machine-learning pipeline: measurements are computed from the night by signal processing, then a model maps them to a risk. Each block is a separate, replaceable step.

How logistic regression turns 51 numbers into a risk

z    = w1·x1 + w2·x2 + … + w51·x51 + b        (weighted sum of the scaled inputs)
risk = 1 / (1 + e^(−z))                       (sigmoid: squashes z into 0–1)

The weights w are learned from the training data. A positive weight means a higher value of that input raises the risk. C = 0.1 is strong regularisation: it keeps the weights small, so the model cannot latch onto noise in any single input.

How the pipeline is evaluated

MethodTrain onTest onAnswers
Repeated 5-fold cross-validation4/5 of peopleRemaining 1/5, rotated; repeated 10 timesHow well does it work on new people?

Metric: age-conditioned AUROCOnly compares people within 2 years of ageDoes sleep add information beyond age?

6. Step-by-step guide

How to reproduce every result in this project, in order.

A. Set up (once)

cd "D:\Ai agent"
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

B. Part 1: sleep-stage network

  1. Get the data: download Sleep-EDF Expanded from PhysioNet into Dataset/.
  2. Preprocess: python preprocess.py filters, cuts into epochs and normalises every recording into data/sleep_edf/.
  3. Train: python train.py trains the CNN + GRU with early stopping and saves the best model to checkpoints/sleep_stager.pt.
  4. Evaluate: python evaluate.py scores the saved model on the 20 test recordings.
  5. Plots: python plots.py draws the confusion matrix, training curves and hypnogram.
  6. Baseline: python features.py then python baseline.py for the logistic-regression comparison.

C. Part 2: cognitive impairment risk

  1. Extract features: with the Challenge 2026 dataset available, run python hsp_features.py <path to the data>. It writes hsp_features.csv, one row per night (about 3 hours for the large set).
  2. Collect the table: put hsp_features.csv and the dataset's demographics.csv in data/hsp_large/.
  3. Train and test the models: python hsp_baseline.py data/hsp_large runs cross-validation and leave-one-hospital-out for all four models.
  4. Explain: python hsp_explain.py data/hsp_large computes SHAP values, risk groups and worked examples.
  5. Results are saved in results/ with the prefix hsp_large_.
